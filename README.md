# Final Project – Netflix Style Web Application

פרויקט גמר בקורס **פיתוח אפליקציות אינטרנטיות**. המערכת מדמה שירות צפייה בסגנון Netflix ומאפשרת הרשמה והתחברות, בחירת פרופיל, צפייה בפיד אישי, ניהול תכנים, היסטוריית צפייה, ביקורות, חיפושים, גרפים, מפה ושימוש בשירות Web חיצוני.

הפרויקט נכתב בכוונה בצורה פשוטה וברורה שמתאימה לרמת הקורס. הוא משתמש בארכיטקטורת MVC ואינו משתמש ב-React, Angular, TypeScript או Framework מתקדם אחר.

## התקנה והפעלה ב-WebStorm

### 1. פתיחת הפרויקט

1. פותחים את WebStorm.
2. לוחצים `Open`.
3. בוחרים את התיקייה:

```text
C:\Users\shach\WebstormProjects\finalProject
```

4. ממתינים עד ש-WebStorm יסיים לסרוק את הקבצים.

### 2. התקנת Dependencies

פותחים את ה-Terminal של WebStorm ומריצים:

```powershell
npm install
```

הפקודה קוראת את `package.json` ומתקינה את החבילות בתוך `node_modules`.

### 3. יצירת קובץ הסביבה

מעתיקים את `.env.example` לקובץ חדש בשם `.env` ומגדירים:

```env
PORT=3000
MONGODB_URI=mongodb://127.0.0.1:27017/final_project
SESSION_SECRET=replace_with_a_private_secret
```

- `PORT` – הפורט שעליו השרת יפעל.
- `MONGODB_URI` – כתובת מסד MongoDB המקומי ושם מסד הנתונים.
- `SESSION_SECRET` – מחרוזת פרטית המשמשת לחתימת ה-Session.

אין להעלות את `.env` ל-GitHub, ולכן הוא מופיע בתוך `.gitignore`.

### 4. הפעלת MongoDB מקומי

יש לוודא ששירות MongoDB פועל. ב-Windows אפשר לבדוק דרך `Services`, או דרך PowerShell בהתאם לאופן ההתקנה.

כאשר MongoDB פועל, הפרויקט מתחבר לכתובת:

```text
mongodb://127.0.0.1:27017/final_project
```

### 5. הוספת נתוני דוגמה

מריצים פעם אחת:

```powershell
npm run seed
```

אפשר להריץ שוב בבטחה: הסקריפט בודק כותרות קיימות ואינו יוצר תוכן כפול בעל אותה כותרת.

### 6. הפעלת השרת

```powershell
npm start
```

ב-Terminal אמורות להופיע ההודעות:

```text
Server is running on http://localhost:3000
Connected to MongoDB
```

פותחים בדפדפן:

```text
http://localhost:3000
```

כדי לעצור את השרת לוחצים `Ctrl + C` בתוך ה-Terminal.

## זרימת השימוש במערכת

1. המשתמש נכנס לדף הראשי `/`.
2. המשתמש נרשם דרך `/register` או מתחבר דרך `/login`.
3. השרת בודק את הנתונים ויוצר Session.
4. המשתמש מועבר ל-`/choose-profile`.
5. המשתמש בוחר פרופיל קיים או עובר ליצירת פרופיל.
6. מזהה הפרופיל הנבחר נשמר ב-`localStorage` של הדפדפן.
7. המשתמש מועבר ל-`/feed`.
8. הדפדפן מבקש מהשרת את `/api/feed/:profileId`.
9. השרת בודק שהפרופיל שייך למשתמש המחובר.
10. השרת מחזיר המלצות, המשך צפייה, Top 10, כל התכנים וביקורות.
11. המשתמש יכול לעבור למסכי פרופילים, היסטוריה, ביקורות, חיפוש, גרפים ושירותים.
12. אם המשתמש הוא מנהל, הוא יכול גם לנהל תכנים ומשתמשים.

זרימת בקשת API רגילה:

```text
HTML + JavaScript בדפדפן
        ↓ fetch
Route ב-Express
        ↓
Middleware של הרשאה
        ↓
Controller
        ↓
Model של Mongoose
        ↓
MongoDB
        ↓ JSON
הדפדפן מעדכן את המסך
```

## ארכיטקטורת MVC

הפרויקט שומר על חלוקה פשוטה של MVC:

- **Model** – מגדיר את מבנה הנתונים ומבצע פעולות מול MongoDB.
- **View** – קובצי HTML המציגים את ממשק המשתמש.
- **Controller** – מקבל בקשה, מבצע Validation ולוגיקה, פונה ל-Model ומחזיר תשובה.
- **Routes** – מחברים בין כתובת HTTP לבין Controller מתאים.
- **public** – קובצי JavaScript, CSS ותמונות של צד הלקוח.
- **middleware** – בדיקות משותפות של התחברות והרשאה.
- **config** – הגדרות משותפות, כרגע חיבור למסד הנתונים.

דוגמה ליצירת פרופיל:

1. `views/profiles.html` מציג טופס.
2. `public/js/profiles.js` קורא את הנתונים ושולח `POST /api/profiles`.
3. `routes/profileRoutes.js` בודק התחברות ומפעיל `createProfile`.
4. `controllers/profileController.js` מאמת את הנתונים ויוצר רשומה.
5. `models/Profile.js` מגדיר כיצד הרשומה נשמרת ב-MongoDB.
6. ה-Controller מחזיר JSON והדפדפן מרענן את הרשימה.

## מבנה מסד הנתונים

### User

מייצג חשבון התחברות אחד.

| שדה | סוג | הסבר |
|---|---|---|
| `username` | String | שם משתמש, חובה, לפחות 3 תווים וייחודי. |
| `email` | String | אימייל, חובה, נשמר באותיות קטנות וייחודי. |
| `password` | String | סיסמה מוצפנת, לא הסיסמה המקורית. |
| `role` | String | `user` או `admin`; ברירת המחדל היא `user`. |
| `createdAt` | Date | נוסף אוטומטית על ידי Mongoose. |
| `updatedAt` | Date | נוסף ומתעדכן אוטומטית. |

### Profile

מייצג פרופיל צפייה השייך לחשבון משתמש.

| שדה | סוג | הסבר |
|---|---|---|
| `user` | ObjectId | הפניה אל המשתמש בעל הפרופיל. |
| `name` | String | שם הפרופיל, חובה ולפחות 2 תווים. |
| `age` | Number | גיל בין 1 ל-120. |
| `favoriteCategories` | Array of String | רשימת קטגוריות מועדפות לצורך המלצות. |
| `createdAt`, `updatedAt` | Date | תאריכי יצירה ועדכון אוטומטיים. |

### Content

מייצג סרט או סדרה.

| שדה | סוג | הסבר |
|---|---|---|
| `title` | String | שם התוכן. |
| `description` | String | תיאור התוכן. |
| `category` | String | קטגוריה, לדוגמה Drama או Action. |
| `type` | String | `movie` או `series`. |
| `releaseYear` | Number | שנת יציאה. |
| `rating` | Number | ציון בין 0 ל-10. |
| `videoUrl` | String | כתובת טריילר או דף צפייה. |
| `imageUrl` | String | כתובת תמונת הפוסטר. |
| `address` | String | כתובת הקשורה למיקום צילום ומוצגת במפה. |
| `createdAt`, `updatedAt` | Date | תאריכי יצירה ועדכון אוטומטיים. |

### WatchHistory

מייצג אירוע או מצב צפייה של פרופיל בתוכן.

| שדה | סוג | הסבר |
|---|---|---|
| `user` | ObjectId | המשתמש בעל הרשומה. |
| `profile` | ObjectId | פרופיל הצפייה. |
| `content` | ObjectId | הסרט או הסדרה שנצפו. |
| `watchedMinutes` | Number | מספר הדקות שנצפו, החל מ-0. |
| `completed` | Boolean | האם הצפייה הושלמה. |
| `watchedAt` | Date | זמן הצפייה, ברירת המחדל היא זמן היצירה. |
| `createdAt`, `updatedAt` | Date | תאריכי יצירה ועדכון אוטומטיים. |

### Review

מייצג ביקורת שמשתמש כתב על תוכן.

| שדה | סוג | הסבר |
|---|---|---|
| `user` | ObjectId | המשתמש שכתב את הביקורת. |
| `content` | ObjectId | התוכן שעליו נכתבה הביקורת. |
| `rating` | Number | ציון חובה בין 1 ל-10. |
| `text` | String | טקסט חובה, עד 500 תווים. |
| `createdAt`, `updatedAt` | Date | תאריכי יצירה ועדכון אוטומטיים. |

## הסבר מלא על מבנה התיקיות והקבצים

### קבצים בתיקייה הראשית

#### `server.js`

קובץ הכניסה הראשי של האפליקציה. הוא:

- טוען את משתני הסביבה.
- יוצר אפליקציית Express.
- מגדיר קריאת JSON וטפסים.
- מגדיר Session ל-24 שעות.
- חושף את התיקייה `public` כקבצים סטטיים.
- מדפיס כל בקשה ל-Terminal לצורך מעקב.
- מחבר את כל קבוצות ה-Routes תחת `/api`.
- מגדיר את כתובות דפי ה-HTML.
- מגן על דפים פרטיים באמצעות Middleware.
- מפעיל את השרת ומתחבר ל-MongoDB.

#### `package.json`

קובץ ההגדרות של פרויקט Node.js. הוא כולל שם וגרסה, פקודות npm ורשימת Dependencies. זהו קובץ JSON ולכן אי אפשר להוסיף בתוכו הערות JavaScript חוקיות.

#### `package-lock.json`

קובץ שנוצר אוטומטית על ידי npm. הוא שומר את הגרסה המדויקת של כל חבילה ותתי-החבילות, כדי שכל חברי הצוות יתקינו אותה סביבת עבודה. לא עורכים אותו ידנית ולא מוסיפים לו הערות.

#### `.env.example`

דוגמה למשתני הסביבה הדרושים. הקובץ אינו מכיל סוד אמיתי ואפשר להעלות אותו ל-Git. כל מפתח בו כולל הסבר קצר.

#### `.env`

קובץ מקומי שאמור להיווצר אצל כל מפתח. הוא מכיל את החיבור למסד ואת סוד ה-Session. הקובץ אינו נשמר ב-Git.

#### `.gitignore`

מגדיר ל-Git אילו קבצים ותיקיות לא להעלות: `node_modules`, קובץ `.env`, הגדרות אישיות של WebStorm וקובצי Log.

#### `README.md`

המסמך הנוכחי. מטרתו להסביר לחברי הצוות ולבודק איך להתקין, להפעיל, להבין ולבדוק את הפרויקט.

### תיקיית `config`

#### `config/database.js`

מכילה את הפונקציה `connectDatabase`. הפונקציה קוראת את `MONGODB_URI`, מנסה להתחבר דרך Mongoose, מדפיסה הצלחה, ובמקרה של כישלון מדפיסה שגיאה ומסיימת את התהליך.

### תיקיית `models`

#### `models/User.js`

מגדיר את `userSchema` ואת Model בשם `User`. אחראי על שדות ההתחברות והתפקיד ועל כללי בסיס כמו שדות חובה וייחודיים.

#### `models/Profile.js`

מגדיר את `Profile`. כל פרופיל מקושר ל-User ושומר שם, גיל וקטגוריות מועדפות.

#### `models/Content.js`

מגדיר את `Content`. שומר את כל פרטי הסרט או הסדרה, כולל פוסטר, טריילר, ציון וכתובת למפה.

#### `models/WatchHistory.js`

מגדיר את `WatchHistory`. מקשר בין User, Profile ו-Content ושומר דקות צפייה ומצב השלמה.

#### `models/Review.js`

מגדיר את `Review`. מקשר ביקורת אל משתמש ותוכן ושומר ציון וטקסט.

#### `models/.gitkeep`

קובץ ריק ששימש בתחילת הפרויקט כדי ש-Git ישמור את התיקייה גם לפני שנוצרו Models. אפשר להשאיר אותו; אין לו השפעה על הרצת המערכת.

### תיקיית `controllers`

#### `controllers/authController.js`

מכיל ארבע פונקציות:

- `register` – בודקת נתונים, מונעת כפילות, מצפינה סיסמה, יוצרת משתמש ו-Session.
- `login` – מוצאת משתמש, משווה סיסמה מוצפנת ויוצרת Session.
- `logout` – מוחקת את ה-Session.

## אימות והרשאות

### הצפנת סיסמה

בהרשמה מופעל:

```javascript
const hashedPassword = await bcrypt.hash(password, 10);
```

המספר `10` הוא מספר סבבי Salt. במסד נשמר Hash ולא טקסט הסיסמה. בהתחברות משתמשים ב-`bcrypt.compare`.

### Session

לאחר הרשמה או התחברות נשמרים ב-Session:

```javascript
req.session.userId = user._id;
req.session.role = user.role;
```

הדפדפן מקבל Cookie שמזהה את ה-Session. בפרויקט סטודנטיאלי זה נעשה באמצעות ברירת המחדל הפשוטה של `express-session`. במערכת Production גדולה נהוג להשתמש ב-Session Store קבוע.

### הרשאות

- משתמש לא מחובר מקבל `401` ב-API מוגן.
- משתמש מחובר שאינו מנהל מקבל `403` בפעולת מנהל.
- דפים מוגנים מעבירים משתמש לא מחובר לדף ההתחברות.
- פעולות פרופיל, היסטוריה וביקורות מסוננות גם לפי `userId`, כדי למנוע גישה למידע של משתמש אחר.

### מחיקה קשורה

במחיקת ישויות מרכזיות ה-Controllers מנקים מידע תלוי במקום להשאיר רשומות שבורות. לדוגמה, מחיקת משתמש מסירה גם פרופילים, היסטוריה וביקורות שלו; מחיקת תוכן מסירה היסטוריה וביקורות הקשורות אליו.

## חיפוש, Aggregation ו-D3

### חיפוש בסיסי

החיפוש משתמש ב-Regular Expression של MongoDB עם האפשרות `i`, ולכן אינו רגיש לאותיות גדולות וקטנות.

### חיפוש מתקדם ראשון

דורש שלושה פרמטרים:

- `category`
- `type`
- `minRating`

ה-Controller בונה אובייקט Filter רק מהערכים שנשלחו.

### חיפוש מתקדם שני

מקבל:

- `title`
- `fromYear`
- `toYear`

כך אפשר לשלב טקסט וטווח שנים באותה שאילתה.

### Aggregation

שני Endpoints משתמשים ב-`Content.aggregate` ובשלב `$group`:

- קיבוץ לפי `category`.
- קיבוץ לפי `type`.

בכל קבוצה מחושבים מספר התכנים וממוצע הציונים.

### D3.js

`charts.js` מקבל את מערכי הסטטיסטיקה ומצייר SVG. בגרף הקטגוריות הקוד יוצר Scale לצירים ומוסיף עמודות. בגרף הסוגים הוא מחשב פרוסות ומציג גרף עוגה של סרטים מול סדרות.

## מפה ושירות חיצוני

### Google Maps

לכל תוכן יכול להיות שדה `address`. המסך טוען את התכנים, מציג אותם ברשימת בחירה ובונה כתובת Google Maps Embed לפי הכתובת שנבחרה.

### TVmaze

הדפדפן אינו פונה ישירות ל-TVmaze. הוא פונה אל:

```text
/api/external/show?title=...
```

ה-Controller בצד השרת:

1. בודק שנשלחה כותרת.
2. מקודד את הכותרת בצורה בטוחה ל-URL.
3. שולח `fetch` אל TVmaze.
4. בודק אם נמצאה סדרה.
5. מחזיר שם, שפה, סטטוס, תאריך התחלה, ז'אנרים, ציון ותקציר נקי מתגי HTML.

זה ממלא את דרישת Web Service חיצוני.

## טיפול בשגיאות ו-Validation

### בצד הלקוח

- שדות HTML משתמשים ב-`required`, סוגי Input מתאימים וטווחים.
- JavaScript מציג הודעות הצלחה ושגיאה שהשרת מחזיר.
- לפני פעולות מחיקה מוצגת בקשת אישור.

### בצד השרת

- כל Controller משתמש ב-`try/catch`.
- שדות חובה נבדקים לפני עבודה מול המסד.
- Mongoose מוסיף כללי Validation מתוך ה-Schema.
- בעלות והרשאות נבדקות לפני עדכון או מחיקה.

קודי HTTP עיקריים:

| קוד | משמעות בפרויקט |
|---|---|
| `200` | הבקשה הצליחה. |
| `201` | רשומה חדשה נוצרה. |
| `400` | קלט חסר או לא תקין. |
| `401` | המשתמש אינו מחובר. |
| `403` | המשתמש מחובר אך חסרה הרשאה. |
| `404` | הרשומה או הסדרה לא נמצאה. |
| `500` | שגיאה פנימית בשרת. |

## נקודות חשובות להגנה

### למה נבחרה ארכיטקטורת MVC?

כדי להפריד בין הנתונים, הלוגיקה והמסכים. כך כל קובץ מקבל אחריות ברורה וקל למצוא ולשנות קוד.

### מה ההבדל בין Route ל-Controller?

ה-Route מגדיר איזו כתובת ואיזו שיטת HTTP מפעילות פעולה. ה-Controller מכיל את הלוגיקה של הפעולה.

### מה עושה Model?

ה-Model מגדיר את מבנה המסמך ב-MongoDB, את סוגי השדות ואת כללי ה-Validation, ומאפשר לבצע שאילתות דרך Mongoose.

### למה גם צד הלקוח וגם צד השרת בודקים קלט?

בדיקת לקוח משפרת את חוויית המשתמש, אך אפשר לעקוף אותה. בדיקת שרת הכרחית כי השרת אינו יכול לסמוך על נתונים שמגיעים מהדפדפן.

### למה צריך Middleware?

כדי לא לחזור בכל Controller על אותה בדיקת התחברות או מנהל. Middleware עוצר בקשה לא מורשית לפני שהיא מגיעה ללוגיקה.

### כיצד נשמרת הסיסמה?

היא עוברת Hash עם bcrypt. במסד לא נשמרת הסיסמה המקורית, ובהתחברות bcrypt משווה את הסיסמה שנשלחה ל-Hash.

### כיצד נמנעת גישה לנתונים של משתמש אחר?

שאילתות של פרופילים, היסטוריה וביקורות כוללות את `req.session.userId`. גם אם נשלח ID של רשומה אחרת, השאילתה לא תחזיר אותה.

### כיצד נבנות ההמלצות?

הפיד קורא את `favoriteCategories` של הפרופיל, מחפש תכנים בקטגוריות האלה וממיין אותם לפי ציון. אם אין העדפות, הוא מציג תכנים מכל הקטגוריות.

### מהו Aggregation?

זהו תהליך עיבוד נתונים בתוך MongoDB. בפרויקט משתמשים ב-`$group` כדי לקבץ תכנים ולחשב כמות וממוצע.

### מה עושה Fetch?

Fetch שולח בקשת HTTP מה-JavaScript בדפדפן אל API של Express, מקבל JSON ומאפשר לעדכן את הדף בלי טעינה מלאה.

### מהו Web Service בפרויקט?

TVmaze הוא שירות חיצוני. השרת שולח אליו שם סדרה ומחזיר לדפדפן נתונים מסודרים.

### למה הפרויקט אינו משתמש ב-React?

מטרת הקורס היא עבודה עם JavaScript, HTML, Express ו-MVC. לכן הממשק נבנה ב-JavaScript פשוט כדי להישאר במסגרת החומר הנלמד.

## עבודה עם Git ו-GitHub

מומלץ שכל שלב יפותח ב-Branch נפרד:

```powershell
git switch main
git pull
git switch -c feature/short-feature-name
```

לאחר שינוי:

```powershell
git status
git add <files>
git commit -m "Short clear message"
git push -u origin feature/short-feature-name
```

לאחר מכן פותחים Pull Request ב-GitHub, בודקים את השינויים וממזגים ל-`main`.

דוגמאות להודעות Commit ברורות:

```text
Add user authentication
Implement content CRUD
Add profile selection
Add charts and external services
Improve project documentation
```

לפני Commit חשוב לוודא:

- שהשרת עולה ללא שגיאות.
- ש-MongoDB מחובר.
- שהתרחיש החדש עובד בדפדפן.
- שלא השתנו קבצים שאינם קשורים למשימה.
- שקובץ `.env` לא נמצא ברשימת הקבצים ל-Commit.
